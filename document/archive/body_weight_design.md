## 背景・課題

現状は `UserPreferences` に「現在の体重」を1つだけ保持しており、
強度ティア・体重比の計算はすべてこの値を使用している。

**問題点：** 体重が変化すると過去のセッションの体重比・ティア評価も遡及して変わってしまう。

---

## 採用候補案

### 案1：セッションごとに体重をスナップショット保存（推奨）

セッション作成時に「その時点の体重」を `WorkoutSession` に記録し、
分析時はそのセッションの体重を使用する。

#### データモデル変更

```dart
class WorkoutSession {
  // 既存フィールド ...
  final double? bodyWeightKg;  // 追加（nullable: 既存データはフォールバック）
}
```

#### 動作仕様

| タイミング | 動作 |
|-----------|------|
| セッション作成時 | `UserPreferences.getBodyWeight()` の値を自動セット |
| 体重を後から修正したい場合 | DailyDetailScreen から該当セッションの体重を編集 |
| 分析画面での計算 | `session.bodyWeightKg ?? currentBodyWeight` を使用 |

#### UIイメージ（DailyDetailScreen）

```
┌────────────────────────────────┐
│ ベンチプレス  100kg × 5        │
│ 体重: 72.0kg  ✎                │  ← タップで編集可能
│ 体重比: 1.39x  [上級]          │
└────────────────────────────────┘
```

#### メリット
- 過去の記録が現在の体重変更の影響を受けない
- 入力ミス時にセッション単位で修正可能
- 他セッションへの影響なし

#### デメリット
- `WorkoutSession` モデル変更が必要
- SQLite マイグレーション（nullable フィールド追加）が必要
- Firestore スキーマも更新が必要

#### 既存データへの対応
- `bodyWeightKg` が null の既存セッションは現在の体重をフォールバックとして使用
- マイグレーションは破壊的変更なし

---

### 案2：体重履歴ログを保持

`(日付, 体重)` のリストを保存し、分析時に「その日時点の体重」を参照する。

- メリット：セッションモデルを変えなくて済む
- デメリット：実装が複雑。体重変更を都度ログに記録する仕組みが必要

---

### 案3：現状維持

- 体重変動が小さい・短期利用ユーザーには許容範囲
- 長期利用・体重管理を重視するユーザーには不正確
