# Git かんたんガイド（非エンジニア向け）

## Git って何？

**アプリのファイルの「セーブポイント」を作る仕組み**です。

ゲームのセーブと同じで、うまくいっているときに保存しておけば、あとで何か壊れても「あの時点」に戻れます。

| 用語 | ひとことで言うと |
|---|---|
| **コミット** | セーブすること（1回のセーブ = 1コミット） |
| **ブランチ** | セーブデータの「分岐ルート」。本番に影響させず試せる作業用コピー |
| **main** | 本番用のメインルート。ここは直接いじらない |
| **ステージ（add）** | 「次のセーブに含めるファイル」を選ぶこと |

---

## いちばん大事な基本の流れ（これだけ覚えればOK）

作業が一区切りついたら、ターミナルで**この4行を上から順に**実行します。

```bash
git status                      # ① 何が変わったか確認する
git add -A                      # ② 変更をぜんぶセーブ対象にする
git commit -m "何をしたかの説明"   # ③ セーブする
git log --oneline -3            # ④ ちゃんとセーブできたか確認する
```

`"何をしたかの説明"` の部分に、変更内容を日本語で書きます。

例：`git commit -m "休憩タイマーの通知を追加"`

> 💡 ターミナルは、プロジェクトのフォルダ（`kintorekioku`）を開いた状態で使ってください。

---

## 作業を始める前にやること（ブランチを作る）

**`main` に直接セーブしないのが鉄則**です。失敗したときに本番のデータまで巻き込まないためです。

新しい作業を始めるときは、最初に作業用の「分岐ルート」を作ります。

```bash
git checkout -b feature/作業内容の名前
```

例：`git checkout -b feature/rest-timer`

（名前は英数字とハイフンで、何の作業かわかるものにします）

**いま自分がどのルートにいるか確認したいとき：**

```bash
git branch --show-current
```

`main` と表示されたら、先に上のコマンドで作業用ブランチを作ってから作業を始めましょう。

---

## 作業が終わって、本番（main）に反映したいとき

```bash
git checkout main                       # 本番ルートに戻る
git merge feature/作業内容の名前          # 作業内容を本番に取り込む
```

> ⚠️ ここは影響が大きい操作です。迷ったら実行する前にエンジニアに確認してください。

## コミットメッセージの書き方

先頭に「何の変更か」を示す言葉を付けると、あとで履歴を見たときにわかりやすくなります。

| 先頭の言葉 | 意味 | 例 |
|---|---|---|
| `feat:` | 新しい機能を追加した | `feat: メモ機能を追加` |
| `fix:` | 不具合を直した | `fix: 入力できない問題を修正` |
| `docs:` | 説明書（ドキュメント）だけ変えた | `docs: ガイドを更新` |
| `chore:` | バージョン更新などの雑務 | `chore: バージョンを1.2.7に更新` |

---

## アプリのバージョンを上げたとき

1. `pubspec.yaml` の `version` を書き換える
2. `document/CHANGELOG.md` の**一番上**に、変更内容を書き足す（[CHANGELOG.md](CHANGELOG.md)）
3. 基本の流れでセーブする
   ```bash
   git add -A
   git commit -m "chore: バージョンを X.Y.Z に更新"
   ```
4. （おすすめ）バージョン名の「しおり」を付けておく
   ```bash
   git tag vX.Y.Z+N
   ```
   しおりを付けておくと、あとで「前のバージョンから何が変わったか」を調べやすくなります。

## 困ったときの早見表

| こんなとき | 使うコマンド |
|---|---|
| 何が変わったか見たい | `git status` |
| 過去のセーブ一覧を見たい | `git log --oneline` |
| セーブ前の変更を、元に戻したい（**変更が消えます**） | `git restore ファイル名` |
| 間違えて `git add` した（セーブ対象から外したい） | `git restore --staged ファイル名` |
| 作業途中の変更を、いったん脇に置いておきたい | `git stash` |
| 脇に置いた変更を戻したい | `git stash pop` |
| 直前のセーブのメッセージを直したい | `git commit --amend` |

## 絶対に守ること

- ❌ **`main` に直接セーブしない**（必ずブランチを作ってから）
- ❌ **パスワードや署名鍵などの秘密のファイルを含めない**
  - 対象：`key.properties`、`reprank-release.jks`、`.env.txt` など
  - これらは自動で除外される設定になっていますが、`git status` の一覧に出てきたら**セーブせず**エンジニアに相談してください
- ❌ **よくわからないコマンドを実行しない**（特に `reset --hard`、`push --force` は変更が完全に消える・他の人の作業を壊す危険があります）
- ✅ セーブする前に **必ず `git status` で中身を確認する**（関係ないファイルが混ざっていないか見る）
- ✅ 迷ったら**実行前に相談する**

## 用語の補足

- **ターミナル**：文字でコンピュータに命令する画面。`git ○○` と打って Enter で実行します
- **リモート**：ネット上（GitHubなど）にあるバックアップ用の保管場所
- **プッシュ（push）**：手元のセーブをネット上の保管場所に送ること（`git push origin ブランチ名`）。他の人と共有したいときに使います
